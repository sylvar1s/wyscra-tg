# Изменения

## Не выпущено

- **Long polling больше не подтверждает незавершённые апдейты ни в каком случае.** В 0.2.0, если медленный обработчик удерживал offset и Telegram присылал только уже полученные апдейты, offset сдвигался за медленный апдейт, и при падении процесса тот терялся. Теперь незавершённые апдейты сначала сохраняются в базу бота (коллекция `wyscra_updates_<id бота>`) и только потом подтверждаются. После перезапуска они обрабатываются заново. При этом бот не стоит, даже если обработчик ждёт ответа пользователя (`ctx.ask`) несколько минут. С базой в памяти (по умолчанию) копия, как и остальные данные, не переживает перезапуск, поэтому для гарантии нужна постоянная база (`db: 'bot.db'` и т.п.). `dropPendingUpdates: true` очищает и эту очередь.
- **MongoDB:** служебная версия записи теперь хранится в поле `__wyscra_rev`, а не в `_v`. Пользовательское поле `_v` больше не перезаписывается и не пропадает при чтении. Записи, сохранённые 0.2.0, продолжают работать.
- **MongoDB:** фильтр `{ поле: null }` больше не совпадает с массивами, содержащими `null`. Поведение теперь такое же, как в остальных базах.
- **Тесты:** mock Bot API реализует настоящую семантику offset: апдейт хранится до подтверждения и учитывается `limit`. Добавлены тесты с аварийным завершением процесса.

## 0.2.0

**Надёжность**
- Long polling подтверждает апдейт только после того, как его обработчик завершился. Если процесс упадёт посреди обработки, Telegram пришлёт апдейт снова (раньше терялось до `concurrency` апдейтов). Финальное подтверждение в `bot.stop()` отправляется после завершения обработчиков.
- `collection.update()` и `increment()` теперь атомарны во всех драйверах: SQLite — `BEGIN IMMEDIATE`, PostgreSQL/MySQL — транзакция с `SELECT … FOR UPDATE` и повтором при deadlock, MongoDB/Redis — compare-and-swap. Свой драйвер может реализовать `Driver.update`; без него изменения одной записи сериализуются внутри процесса.
- Фильтры `find({...})` и `count({...})` работают одинаково во всех БД: строгое равенство (`5` ≠ `'5'`, `true` ≠ `1`, значение ≠ массив с ним), `null` — «null или поля нет», объекты и массивы сравниваются целиком.
- Повреждённый файл `data.json`, `sessions.json` или файл сессии MTProto больше не заменяется молча пустыми данными: вместо этого выдаётся понятная ошибка, а файл остаётся нетронутым. Одна повреждённая запись в SQLite/Redis пропускается в `find()` с предупреждением.

**MTProto**
- Шифрование сессий: `new TelegramClient({ ..., sessionPassword })`, `new FileSession(path, { password })`, `client.exportSession(password)` / `new StringSession(str, { password })` — AES-256-GCM с ключом из scrypt. Открытый файл сессии перешифровывается при следующем сохранении.

**Тесты**
- Общий набор тестов для всех драйверов БД; в CI поднимаются PostgreSQL, MySQL, MongoDB и Redis (node-redis и ioredis).

## 0.1.0 — первый выпуск

**Bot API**
- Все 193 метода и 425 типов Bot API 10.4, сгенерированы из официальной спецификации (`npm run update-api`).
- Клавиатуры массивами, кнопки с `onClick`, удобные опции (`html`, `silent`, `replyTo`, `removeKeyboard`...).
- Команды, `hears`, `action`, фильтры `on('photo')` с сужением типов, middleware, Composer.
- `ctx.ask`, сцены (переживают перезапуск), сессии и `ctx.user` без настройки.
- Встроенная база данных: SQLite, JSON, память; PostgreSQL, MySQL, MongoDB, Redis через драйверы.
- Рассылка, статистика, админ-панель `/admin` с выгрузкой в CSV.
- Модерация групп (`ban`, `mute`, `kick`, `isAdmin`, `isSubscribed`).
- Оплата звёздами (`invoice`, `onPayment`, `refund`), inline-режим, `paginate`.
- Переводы с формами множественного числа, задачи по расписанию (every/daily/cron/once), антиспам.
- Проверка данных мини-приложений и Telegram Login Widget.
- Соблюдение лимитов Telegram, повтор при 429, кэш `file_id`, вебхуки (Node, Express, Bun, Deno, Cloudflare, Vercel).
- `npx wyscra-tg init` — создание проекта одной командой.

**MTProto**
- Клиент для юзерботов и ботов: слой 233, все 877 методов с типами.
- Вход по номеру/коду/2FA или токену бота, сессии в файле или строке.
- Переходы между DC, FLOOD_WAIT, переподключение, контроль пропущенных обновлений.
- Отправка и скачивание файлов, история, диалоги, участники.
- Обфусцированный транспорт, SOCKS5, MTProxy.
